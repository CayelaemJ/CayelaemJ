## Direct technical examples
1. **SQL grain, joins and quality:** Identified manifest schedule fan-out; documented source-of-truth carrier-truck-driver joins; avoided deduplication that would erase delivery rows.
2. **DAX semantic correctness:** Separately averaged eligible daily scrap and production by state; handled duplicate schedule grains; distinguished stock, flow and historical observation dates.
3. **Power BI operational reliability:** Resolved dynamic pivot drift, SQL deadlocks, broken cross-dataflow dependencies, localized source-code conversions and unusual production-unit errors.
4. **Data ingestion contracts:** Designed canonical ten-feed SQL/API/file validation and kept source credentials off the browser.
5. **Multi-tenant systems:** Built or explored server-side membership checks, PostgreSQL RLS, auditability, session protection, role approvals and synthetic demos.
6. **Product-centered AI:** Kept AI explanations separate from financial entries and teacher-reviewed academic grading; model routing needs failover testing.
7. **Testing and operational cost:** Prefer disposable synthetic PostgreSQL in local Docker, free-tier-aware hosting, reversible migrations and clear release-readiness gates.

## Professional application positioning
- **Primary:** Data Engineer · Analytics Engineer · Senior BI / Power BI Developer · Full-Stack / Platform Engineer
- **Adjacent:** Automation Engineer · Product/Applied AI Engineer · Forward-Deployed Engineer · Data/BI Solutions Architect
- **Career direction:** Technical leadership / engineering architecture / CTO-track growth.

## Important honesty notes
- “Used in training”, “researched”, “implemented in a branch”, “tested locally”, “staging” and “live production” are different statuses; describe them precisely.
- A native mobile roadmap does not prove app-store release or parity.
- A configured AI provider does not demonstrate reliability until calls, routing and fallback are tested.
- Security controls do not imply formal certification.
- Date-sensitive CV achievements and metrics should be verified against engagement evidence before external tender or contract claims.
